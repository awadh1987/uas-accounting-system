## 2. Subtle Compound Integration Failure Found During Trace

Look closely at **Worker Wage Deletion & Update (`workers/[id]/route.ts` & `workers/route.ts`)**:
- `postWorkerWageJournalTx()` ([ledgerService.ts:L1347-1414](file:///e:/2026/uas-accounting-system/src/lib/accounting/ledgerService.ts#L1347-L1414)) creates **TWO** separate `JournalEntry` rows when `creditAmount > 0`: (1) `accrual` (`WRK-ACC-...`, linked via `sourceId = entry.id`), and (2) `payout` (`WRK-PAY-...`, also `sourceId = entry.id`), returning **only `accrual`** to be saved in `WorkerWageEntry.journalEntryId` (`workers/route.ts:L103-107`).
- When updating via `updateWorkerWageAtomic` (`ledgerService.ts:L3138-3149`), the code queries `where: { sourceId: existing.id }` so it finds and reverses *both* accrual and payout entries.
- **HOWEVER**, when deleting via `DELETE /api/workers/[id]` ([workers/[id]/route.ts:L99-106](file:///e:/2026/uas-accounting-system/src/app/api/workers/%5Bid%5D/route.ts#L99-L106)), the code **only reverses `rec.journalEntryId`**! The second `WORKER_PAYOUT` journal entry (`WRK-PAY-...`) is **NEVER reversed and remains permanently posted in the General Ledger**, leaving a ghost debit to the worker and ghost credit to Cash!
